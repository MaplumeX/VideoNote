# 重新设计笔记详情页（排版与交互流程）

## Goal

重新设计笔记详情页（`NoteDetailPage`）的排版与交互流程，提升阅读体验和操作效率。用户对当前界面的不满集中在排版和交互流程（"排版 交互流程 等等"）。

## Background（现状分析，来自代码勘察）

### 当前页面结构（frontend/src/pages/NoteDetailPage.tsx，约 530 行）

三栏布局：
1. **左侧边栏（w-56，sticky）**：面包屑导航、下载 Markdown 按钮、收藏按钮、保存状态文字、标签管理（chips + 行内输入框 + 建议下拉）、文件夹选择器（下拉树）、播放视频按钮。
2. **中间主体（flex-1）**：Milkdown WYSIWYG 编辑器（`NoteEditor`，支持 KaTeX/Mermaid/时间戳徽章）。
3. **右侧（TOC）**：`TableOfContents`，基于 IntersectionObserver 的 h2/h3 目录。

另有处理中状态视图（`StepIndicator` 进度）和浮动视频播放器（`VideoPlayerFloat`，点击时间戳徽章跳转）。

### 现状的排版/交互问题（勘察结论）

- **P1** 左侧边栏承载了过多低频操作（下载/收藏/文件夹/播放），占据 224px 固定宽度，挤压正文阅读空间；标签管理（输入+建议+删除）塞在窄栏里，交互局促。
- **P1** 无标题区：笔记标题只在面包屑里以小字截断显示，页面缺乏明确的标题/元信息区（创建时间、来源平台等不可见）。
- **P1** 窄屏（<lg）无响应式处理：三栏固定布局在小屏会严重挤压；TOC 无折叠机制。
- **P2** 保存状态只以一行小字出现在侧栏，位置不显眼；处理中/失败状态复用 error 分支展示，失败时丢失视频信息卡上下文。
- **P2** 操作入口分散：面包屑在左栏顶部，与全局侧栏（`Sidebar`/`AppLayout`）的关系未理顺；返回历史页只能点面包屑小链接。
- **P2** 文件夹选择器和标签建议下拉为手写实现，无焦点管理/键盘导航/Esc 关闭外点击关闭（folder picker 打开后无外点关闭逻辑）。

### 技术约束（来自 spec 与代码）

- Tailwind CSS only，禁 inline style（CSS 变量 + arbitrary value 例外）。
- shadcn/ui（@base-ui/react 基座）组件优先；`render` prop 而非 `asChild`。
- 笔记渲染 Milkdown-only，无独立 HTML 预览管线。
- 既有自定义节点：timestamp-badge（点击跳视频）、KaTeX、Mermaid——重设计不得破坏。
- 自动保存管线（`useNoteAutoSave`）、SSE 处理中状态流（`useSSE`）行为需保留。
- 项目有 i18n（react-i18next），新 UI 文案需走 t()。
- frontend 层 spec：命名导出、Props 接口在组件上方。

## Requirements

### R1 标题/头部区

- 页面顶部新增标题区：笔记标题（大字、完整显示不截断）、来源元信息（平台/文件名、创建时间若有 API 数据）、返回入口。
- 标题区常驻可见（sticky 或滚动固定），不遮挡正文。

### R2 操作整合

- 下载、收藏、播放视频等操作从左栏移到头部区的紧凑操作区（图标按钮 + Tooltip 或 DropdownMenu）。
- 收藏状态有明确视觉反馈（填充星形/高亮）。

### R3 标签与文件夹

- 标签与文件夹管理整合为头部区的 Popover/DropdownMenu 交互（或统一"笔记信息"入口），不再占用固定侧栏空间。
- 文件夹选择器补齐：点击外部关闭、Esc 关闭。
- 标签输入保留建议列表，增加键盘上下选择 + Enter 确认（如成本允许，可降级为现有行为，需在验收中注明）。

### R4 阅读优先的正文排版

- 正文区域最大化：去掉左固定栏后，正文占满主要宽度，采用适合长文阅读的最大宽度约束（如 max-w-3xl/4xl 居中）。
- TOC 保留在右侧（宽屏），中窄屏收纳为可开关的抽屉/浮层（Sheet 或悬浮按钮）。

### R5 响应式

- 窄屏（<lg）单列布局：头部 + 正文，操作收进 DropdownMenu，TOC 收进抽屉。
- 不要求支持移动端触控专项优化，但布局不得破损。

### R6 保存/处理状态

- 保存状态（保存中/已保存/失败）显示在头部区或编辑器附近显眼位置。
- 处理中状态视图保持现有 StepIndicator 流程，但失败态保留视频信息卡与重试按钮（不丢失上下文）。

### R7 不变项（兼容）

- Milkdown 编辑器功能（自定义节点、时间戳点击跳转视频、自动保存）行为不变。
- API 调用、数据流、路由（/app/notes/:id）不变。
- History/Dashboard 等其他页面不改动（除必要的共享组件微调）。

## Acceptance Criteria

- [ ] AC1 页面顶部有标题区，显示完整笔记标题、来源元信息、返回入口；正文不再被 224px 固定侧栏挤压。
- [ ] AC2 下载/收藏/播放操作可从头部区触达；收藏切换有视觉状态变化。
- [ ] AC3 标签可添加/删除、文件夹可切换，均在头部区交互内完成；文件夹选择器支持外点关闭和 Esc。
- [ ] AC4 宽屏（≥lg）正文以阅读友好宽度居中，右侧 TOC 正常工作（高亮滚动联动）。
- [ ] AC5 窄屏（<lg，如 375px 宽）布局不破损：无横向滚动条，操作可触达，TOC 可通过开关访问。
- [ ] AC6 编辑内容后自动保存状态在显眼位置可见（保存中→已保存/失败）；刷新后内容保留。
- [ ] AC7 处理中笔记页显示进度；失败时仍显示视频信息卡 + 重试按钮；取消/重试流程可用。
- [ ] AC8 时间戳徽章点击后视频播放器弹出并跳转对应时间（回归验证）。
- [ ] AC9 `npm run build`（frontend）与现有测试（`npm test`）通过；新增交互有对应测试（至少覆盖文件夹选择器关闭行为、头部操作存在性）。
- [ ] AC10 所有新文案走 i18n t()，zh/en 均有翻译。

## Out of Scope

- 其他页面（History、Dashboard、Settings、NewNote）的改版。
- 后端 API 变更（若元信息需要新字段，先检查现有 API 返回，缺则降级隐藏该元信息）。
- Milkdown 编辑器内核与自定义节点逻辑改动（仅调整容器布局）。
- 移动端专项优化（触控手势、PWA 等）。
- 深色模式新增主题（沿用现有 dark class 机制）。
